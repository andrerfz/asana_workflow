# Asana Workflow Dashboard

A FastAPI-powered dashboard for managing Asana tasks with AI-driven classification, prioritization, and an autonomous coding agent that investigates, plans, implements, tests, and delivers task solutions using Claude Code CLI.

## Features

- **Task Dashboard** — View, filter, and manage Asana tasks in card, table, or cluster views
- **AI Classification** — Automatically classify tasks by type, scope, and priority using Claude
- **AI Coding Agent** — Autonomous agent that reads task requirements, investigates the codebase, creates a plan, writes code, runs tests, performs QA review, and delivers via PR — with human approval gates at each step
- **Real-time Updates** — WebSocket-based live logs, phase transitions, and notifications
- **Agent Guidance** — Send feedback to a running agent mid-coding; it pauses and resumes with your message in context
- **Smart Testing** — Auto-selects fast vs full test suite based on whether migrations are present
- **Git Worktree Isolation** — Each agent task gets its own worktree, keeping your main branch clean
- **Multi-repo Support** — Agent can work across multiple repositories per task
- **IDE Integration** — Open worktrees directly in PhpStorm, VS Code, Cursor, or other IDEs

## Setup (step by step)

### Step 1 — Clone and install dependencies

```bash
git clone <this-repo>
cd asana-workflow
make setup
```

This copies `.env.example` → `.env`, installs Python dependencies, and creates the `data/` directory.

### Step 2 — Get your Asana credentials

You need three values from Asana:

**ASANA_PAT** (Personal Access Token)
→ Go to [https://app.asana.com/0/my-apps](https://app.asana.com/0/my-apps) → *Create new token*

**ASANA_PROJECT_GID** (Project ID)
→ Open your Asana project in the browser. The URL looks like:
`https://app.asana.com/0/1234567890123456/...`
The long number after `/0/` is your project GID.

**ASANA_SECTION_GID** (Section ID — the section whose tasks the dashboard monitors)
→ Use the Asana API explorer or inspect the network tab. Alternatively, use the Asana API:
```bash
curl -H "Authorization: Bearer YOUR_PAT" \
  "https://app.asana.com/api/1.0/projects/YOUR_PROJECT_GID/sections" \
  | python3 -m json.tool
```
Pick the GID of the section you want the dashboard to show.

### Step 3 — Edit `.env`

```env
# Required — Asana integration
ASANA_PAT=your_token_here
ASANA_PROJECT_GID=1234567890123456
ASANA_SECTION_GID=1234567890123457

# Optional — syncs scope scores to this custom field
ASANA_STORY_POINT_FIELD_GID=

# Required for AI Agent feature
# Must be the PARENT directory that contains all your git repos
# Example: if your repos live at ~/Projects/my-app, set this to ~/Projects
PROJECTS_DIR=/Users/youruser/Projects

# Optional — enables AI classification
ANTHROPIC_API_KEY=your_key_here
CLAUDE_MODEL=claude-haiku-4-5-20251001

# Docker GID for socket access
# macOS Docker Desktop: 0
# Linux: run `stat -c '%g' /var/run/docker.sock`
DOCKER_GID=0

# Auto-refresh interval in minutes
POLL_INTERVAL_MINUTES=5

# Claude Code CLI OAuth token (generated by make setup-agent)
CLAUDE_CODE_OAUTH_TOKEN=
```

### Step 4 — Generate Claude Code auth token (required for agent)

Make sure you're logged in to Claude Code on your machine first:

```bash
claude login
```

Then generate a headless token for the container:

```bash
make setup-agent
```

This runs `claude setup-token`, captures the OAuth token, and saves it to your `.env` as `CLAUDE_CODE_OAUTH_TOKEN`. The token is valid for 1 year and lets the agent run Claude Code inside Docker without interactive login.

### Step 5 — Start the dashboard

**Local development (hot reload, no Docker):**

```bash
make dev
```

**Docker (recommended for production use):**

```bash
make build
make up
```

Open [http://localhost:8765](http://localhost:8765)

### Step 6 — Configure repositories in the UI

After opening the dashboard, go to **Settings → Repos** and add each repository the agent should work in:

| Field | Description | Example |
|-------|-------------|---------|
| Path | Absolute path to the repo | `/Users/you/Projects/my-app` |
| Default branch | Branch to rebase onto | `master` or `main` |
| Area tags | Asana task tags that map to this repo | `backend_api`, `frontend` |
| Test command | Full test run (with migrations) | `make agent-test` |
| Fast test command | Skip migrations when none changed | `make agent-test-no-migrations` |
| Test description | Hints to the agent about test modes | *"Use fast unless migrations present"* |

> **Tip:** The agent auto-selects the fast command when the diff has no migration files — this saves several minutes per task.

## Agent Workflow

```
Start → Investigating → Planning → [Human Approval] → Coding → Rebase → Testing → QA Review → [Human Approval] → Done
                            ↑                                                              |
                            └────────────────── Revise / Reject ───────────────────────────┘
```

1. **Investigating** — Agent reads the task, explores the codebase with read-only tools, and produces a findings report
2. **Planning** — Agent proposes an implementation plan based on the investigation
3. **Approval** — You review and approve, reject, or revise the plan with feedback
4. **Coding** — Agent implements the plan in an isolated git worktree using Claude Code CLI
5. **Guide** — Optionally send real-time feedback to redirect the agent mid-coding
6. **Rebase** — Branch is rebased onto the latest default branch
7. **Testing** — Runs your test suite; auto-retries with fixes on failure (up to 3 rounds)
8. **QA Review** — Automated code review against task requirements; PASS auto-approves, FAIL waits for you
9. **Delivery** — Squashes commits, pushes branch, and posts summary to Asana

## Troubleshooting

**Dashboard shows no tasks**
→ Check `ASANA_PAT` and `ASANA_SECTION_GID` are correct. Visit `/api/tasks` to see the raw response.

**Agent fails with "Claude Code not authenticated"**
→ Run `claude login` on your host machine, then `make setup-agent` to regenerate the token, then `make recreate`.

**Agent fails with "No repos configured"**
→ Go to Settings → Repos in the dashboard and add at least one repository with the correct path.

**`make setup-agent` fails with "expect not found"**
→ Install `expect`: `brew install expect` (macOS) or `apt install expect` (Linux).

**Tests always skip with "Sail not running"**
→ The test command uses Docker Compose. Start your project's Sail/Docker services first, or switch to a local test command in Settings → Repos.

**PROJECTS_DIR: permission denied inside container**
→ Make sure `PROJECTS_DIR` is the parent of your repos and is accessible. On macOS, add it to Docker Desktop's file sharing list under Settings → Resources → File Sharing.
